# Contribuciones — Cuaderno de Bachillerato

Gracias por tu interés en este proyecto. Lee esta guía antes de proponer cualquier cambio.

---

## Aviso importante

Este es un proyecto de **uso exclusivement personal**. El propietario se reserva el derecho de aceptar o rechazar cualquier contribución sin necesidad de justificación.

Las contribuciones de código **no se aceptan de forma general**. Si deseas proponer un cambio significativo, abre primero un Issue discutiendo la propuesta antes de invertir tiempo en implementarla.

---

## Reportar errores

Si encuentras un error, abre un Issue en el repositorio con la siguiente información:

- **Descripción clara** del problema
- **Pasos para reproducir** el error
- **Comportamiento esperado** vs. comportamiento actual
- **Navegador y sistema operativo** donde ocurre
- **Captura de pantalla** o mensaje de consola, si es posible

---

## Proponer mejoras

Las propuestas de mejora se reciben a través de Issues. Incluye:

- Una descripción de la funcionalidad propuesta
- El problema que resuelve o la mejora que aporta
- Cualquier alternativa considerada

No envíes Pull Requests sin abrir previamente un Issue de discusión.

---

## Contribuciones de código

Las Pull Requests **no se aceptan** salvo que el propietario haya expresamente solicitado o aprobado el cambio de antemano.

Si crees que puedes mejorar algo del proyecto:

1. Abre un Issue describiendo el cambio propuesto
2. Espera la respuesta del propietario antes de comenzar a programar
3. Si se aprueba, trabaja en una rama separada y envía una Pull Request con una descripción clara de los cambios

---

## Forks

No se permite crear forks del proyecto para:

- Redistribuir versiones modificadas
- Crear obras derivadas
- Publicar el código en otros repositorios o plataformas
- Cualquier uso que no sea estrictamente personal y local

El código está publicado en GitHub únicamente como referencia y respaldo, no como proyecto de código abierto.

---

## Estilo de código

Si se aprueba una contribución de código, mantén consistencia con el código existente:

- TypeScript estricto (`strict: true` en tsconfig)
- Sin frameworks de UI — TypeScript vanilla
- CSS con variables CSS y diseño glassmorphism
- Nombres de archivos en minúsculas
- Funciones y variables en camelCase
- Interfaces y tipos en PascalCase

---

## Commits

Escribe mensajes de commit claros y concisos en español:

- `feat: añadir filtro de fechas en calendario`
- `fix: corregir cálculo de nota EBAU`
- `style: ajustar espaciado en modo oscuro`
- `docs: actualizar README con nuevas funcionalidades`
